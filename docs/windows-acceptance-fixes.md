## 수정

- **QA-01 업로드 판면 유실:** 새 작업을 열 때 업로드 창에서 선택한 Layout/Options/꼬리말을 적용한다. 서버가 지원하지 않는 짝수·번호 범위도 로컬 문서와 SMJ에 남는다. 기존 서버 작업 열기는 서버 설정을 사용한다. B-06 서버 저장 제약은 그대로 알린다.
- **QA-03 버전 조회:** `downloadUrl=null` 또는 필드 누락을 허용한다. 최신/최소 버전은 표시하고 다운로드 주소가 없으면 다운로드를 시작하지 않는다. 필수 업데이트 정책과 잘못된 HTTP·사용자 정보 포함 URL 차단은 유지한다.
- **QA-04 원본 패널:** 파일 업로드는 원본 패널을 기본 표시한다. 서버에서 연 작업은 첫 쪽의 원본 유형을 확인해 PDF/이미지 3패널, 텍스트 2패널로 초기화한다.
- **QA-05 메모:** 해결 항목을 줄 메모·모아보기·여백 표시에서 기본 숨긴다. 해결 항목 포함, 해결 되돌리기, 회신 입력, 본문 수정, 문서 전체 이전/다음 이동을 제공한다. 본문·작성 시각·로컬 ID를 보존한다. 서버 B-05 때문에 해결 상태는 여전히 SMJ에만 남는다.
- **규정 검색:** 우상단 검색칸에서 Enter로 문서와 무관하게 검색한다. 3개 문서 필터, 건수·페이지 이동, 목록 안 단일 항목 펼치기를 제공한다. 서버 원문이 발췌이므로 전문이라고 표시하지 않는다.
- **태그:** 교열이 자동 삽입하는 상자·상자2·상자3·상자끝·네모글·기울임은 메뉴에서 제외한다. 기존 파일 해석은 유지한다.
- **크레딧 상태:** 실제 `creditExhausted` 필드를 읽어 처리된 쪽 수와 중단 안내를 표시한다. 이미 처리된 내용은 편집할 수 있다. 없는 재개 API를 호출하거나 전체 파일 재업로드로 대체하지 않는다.
- **엔진:** v3.4.31 / `9b6434996bdeffa2536551d20cf2bdbcb82ecab5`로 고정한다. 빌드 캐시가 구버전이면 변경 사항이 없는지 확인한 뒤 지정 커밋으로 갱신한다. 편집 좌표를 반환하는 기존 조판 브리지는 유지한다.
- **QA-06 종료 경쟁 조건:** 재검사에서 실제 `ObjectDisposedException`과 종료 코드 `-532462766`을 재현했다. 편집 버퍼 해제 중 발생한 caret 이벤트가 새 debounce를 만들고, 해제된 토큰을 읽었다. 자원 해제 시작 시 새 편집/점역 요청을 막고 세대를 무효화한다. 지연된 응답도 종료 후 상태를 갱신하지 않는다.

## 서버와 엔진 후속 사항

- **QA-02 이미지 변환 실패:** 기존 시험 작업의 원본 2쪽을 다시 받아 비교했다. 1쪽=입력 page-2.png, 2쪽=입력 page-1.png이며 길이와 SHA-256 모두 같다. 파일 바이트·순서가 서버까지 보존됐지만 AI 결과는 `InvalidPDFError`였다. BE→AI 경계 조사 필요. 실패 쪽 재시도를 위해 파일 전체를 재업로드하지 않았다.

- **크레딧 재개:** 읽은 BE dev의 JobController에는 status/cancel/events가 있고 resume/retry가 없다. 이어서 처리·중복 차감 방지는 서버 계약 추가가 필요하다. 실제 크레딧을 소진시키지는 않았다.
- **언어·공백:** v3.4.31 sidecar도 영어 문서 규정·혼용·연속 공백 정책 필드가 없다. 임의 점역 규칙을 추가하지 않았다. [엔진 계약](engine-contract.md)을 따른다.
- 물리 키보드·IME 조합·다중 DPI·스크린리더 청취·실제 점자 프린터·100쪽 원고는 별도 환경 검증이다. 화면 전체의 픽셀 단위 Figma 일치나 모든 P0 항목 인수 완료로 확대 해석하지 않는다.
