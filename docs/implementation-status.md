# 데스크톱 편집기 구현 상태

2026-10-20 기준. [Service 기획](https://app.notion.com/p/3a643813bc2e801aa2b9eaf48dde8f2e)의 최신 ‘세부 기능’을 우선한다. 직접 확정한 예외와 충돌은 [우선순위 기록](service-priority.md)에 있다. **전체 기획 구현 완료 또는 배포 승인 상태는 아니다.**

## 이번 범위

사용자 확정: 현재 데스크톱 편집기를 우선한다. 관리자 웹 대시보드와 서버 폴더·휴지통은 후속 범위다. BE를 변경하지 않고 수정안을 문서화한다. 계정 화면·작업 이력 조회·로컬 작업 폴더는 편집기의 사용 흐름으로 유지한다.

자동 저장은 없다. Ctrl+S·명시적 저장만 .smj와 서버 저장을 요청한다. 실제 점역 엔진은 Semojum/braille v3.4.24다. 영어 문서·혼용 규정·연속 공백 정책의 엔진 확장은 사용자의 결정에 따라 후속 범위로 남긴다. 미확정 6점키 프리셋은 만들지 않고 사용자 지정 키를 제공한다. 문의 주소는 contact-semojum@gmail.com, 운영 기관명은 등록 전이다.

## 앱에서 완료한 잔여 편집·조판

- `compose_editor`는 실제 엔진의 줄 접기·정렬·페이지 숫자·BRF 직렬화를 사용하며, 최종 BRF와 함께 셀→블록/원문 오프셋을 반환한다. 화면용 줄바꿈을 저장하지 않는다. 머리말·페이지행·변경선·괘선은 보호하며 본문만 수정한다.
- 재조판 동안 오래된 마우스 좌표를 막고, 현재 원문 위치에 대한 연속 키 입력은 보존한다. 메인 창과 분리 창은 같은 문서 버전의 조판 결과·편집 이력을 사용한다.
- 원문 쪽 연속 편집은 본문 패널 안에서 드래그·Shift 선택과 편집을 지원한다. 블록을 합치는 대체는 원본 영역·메모 근거를 보존하고 한 번의 Undo로 되돌린다.
- `.smj` v2는 번호 범위·꼬리말 범위별 정렬을 보존한다. 기존 v1을 읽고 다음 명시적 저장에서 v2로 기록한다.

## 합의된 후속 범위와 남은 검증

1. **엔진 후속**: 영어 문서·혼용 규정·연속 공백 정책 확장. 설정에 적용 한계를 표시하고 값을 보존한다. 이번 작업에서 엔진 저장소의 점역 규칙은 변경하지 않았다.
2. **외부 계약**: 첫 점자/새 블록 저장 ID 연결, 실패 쪽 사용자 AI 재시도, 암호 PDF 암호 전달, OCR 신뢰도/미지원 글자 감지. 오류를 성공으로 표시하거나 임의 유료 재업로드로 대체하지 않는다.
3. **사용 환경 검증**: 실제 한국어 IME·키보드 롤오버·스크린 리더·다중 모니터/DPI·대용량 실원고·물리 프린터·운영 배포 업데이트. 자동화된 핵심/UI 검사와 구분한다.

## 백엔드 결함과 후속 범위

2026-10-20 재확인: BE `dev`는 여전히 `5d8dda0a`로 B-01~B-10 제안이 반영되지 않았다. 따라서 C-05~C-10(신규 블록 ID 동기화, 쪽별 결과·재시도, 메모 왕복, 조판 옵션 왕복, 실패 쪽 AI 재시도, PDF 암호·HWP 옵션·OCR 확장)의 서버 연결은 시작하지 않았고, 현재 계약에서 가능한 준비(서버 보유 블록 기록, 품질 보고서 보존, 미보존 항목 안내)만 반영했다.

빈 문서 생성 API는 존재한다. 핵심 저장 결함은 첫 점자와 신규 블록의 ID 매칭이다. [현재 BE 근거와 수정안](backend-save-review.md)에 첫 저장·중복 문장·병합/분할·부분 실패 검증 조건을 기록했다. 앱은 로컬 파일을 먼저 보존하고 서버 실패를 별도로 표시한다.

후속: 관리자 웹(계정/기관/크레딧/공지 운영), 서버 폴더·휴지통(이동/복원/영구 삭제/권한/보관 정책). 초안 약관·파일처리방침은 시행일과 운영 값 확인 없이 확정 정책으로 게시하지 않는다.
