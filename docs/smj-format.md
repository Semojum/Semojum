# 세모점 작업 파일 v4

2026-10-14 사용자 승인: 확장자 `.smj`, 버전 있는 ZIP. 자동 저장은 하지 않는다. Ctrl+S 또는 명시적 저장 때 로컬 파일과 서버 저장을 실행한다. 쪽 이동·종료 자체는 저장하지 않으며 미저장 변경이 있으면 저장/버리기/취소를 선택한다.

`manifest.json`의 `format`은 `semojum-work`, `version`은 4다. 읽기는 v1·v2·v3·v4를 지원한다. 블록의 원문·점자·서버 id·타입·표 구조·초안·음절 경계·수동 수정 표시·줄 메모·텍스트/점자 커서 위치, 조판·점역 옵션·꼬리말, 현재 블록, 작업 id·소유 계정 id·작업 상태, 원본 쪽 정보와 원본 파일 목록을 담는다. 인증 토큰과 비밀번호는 저장하지 않는다. 커서 필드가 없는 초기 v1 파일은 각 블록 시작 위치로 연다. 커서 이동만으로 파일을 자동 저장하거나 미저장 변경 표시를 켜지 않는다.

원본 바이트는 `originals/0000` 형태의 엔트리에 담고 manifest에는 원래 파일명, 길이, SHA-256을 기록한다. URL이 만료되어도 읽을 수 있도록 다운로드된 원본 미리보기도 보존한다. ZIP 엔트리를 디스크 경로로 풀지 않는다. 중복 엔트리·누락 항목·해시 불일치·알 수 없는 버전은 열지 않는다. 확장 크기 512 MiB, manifest 64 MiB 제한이 있다.

저장 시 편집 데이터를 스냅샷으로 복사한 후 같은 폴더의 임시 파일에 쓰고 flush 후 교체한다. 취소나 쓰기 실패 때 기존 파일은 유지한다. 저장 도중의 추가 편집은 저장 완료로 간주하지 않는다. 서버 저장의 부분 실패와 로컬 저장 성공은 따로 알린다.

새 블록은 안정적인 `app_` 클라이언트 ID를 발급하고, 원문과 점자에 같은 ID를 사용한다. 서버 발급 ID가 있으면 우선한다. 최초 점자와 새 블록도 저장하며 ID는 재시도와 다시 열기에서 유지한다. 사용자 승인 없이 저장 작업을 AI 변환이나 유료 작업 생성으로 바꾸지 않는다.

기존 `.mock.smi`는 읽어서 `.smj`로 옮길 수 있는 레거시 목업 형식이며 배포용 규격이 아니다.

2026-10-19 추가 필드: `footerRanges`는 인쇄된 점자 면 번호 기준의 시작·끝·텍스트 배열이다. 끝이 null이면 끝까지, 빈 텍스트면 기본 꼬리말을 숨긴다. 겹치는 범위를 거부한다. 초기 v1 파일의 누락 필드는 빈 배열로 읽는다. 메모의 `resolved`는 초기 파일에서 false로 읽는다. AI 대체 초안·적용 규정·최초 원문은 블록 메타데이터에 함께 보존한다.

동시 편집 방지용 `.smj.lock`과 읽기 전용 상태는 파일 내용이 아니다. 창을 닫으면 쓰기 잠금을 해제한다. 계정별 키·색상·상용구·출력 기본값과 탭 구성은 계정/앱 설정이며 문서에 인증 정보와 함께 섞어 넣지 않는다. 꼬리말 범위 등 서버 미지원 조판 설정을 보존하려면 `.smj`를 사용한다. 메모 작성자·답글·해결 상태는 최신 계약으로 함께 저장한다.

2026-10-20 v2: `layout.numberRanges`는 인쇄 면 번호 기준 `{start, end}` 배열이며 null은 전체 범위다. 홀수/짝수/전체 번호 설정과 교집합으로 적용한다. `footerRanges[].alignment`는 null(기본 정렬 사용) 또는 `left`/`center`/`right`다. v1의 누락 필드는 기본값으로 복원하며 다음 명시적 저장에서 v2로 기록한다. 구버전 앱이 새 설정을 읽고 버린 채 저장하는 것을 방지하려고 형식 버전을 올렸다. v2 파일은 v1만 지원하는 앱에서 열리지 않는다.

셀 좌표·자동 줄바꿈·미리보기 면은 파생 결과이므로 파일에 별도 저장하지 않는다. 원문 점자와 명시적 줄바꿈·쪽바꿈 표식을 저장하고 열 때 다시 조판한다.

2026-10-20 v3: 서버 동기화 보조 정보를 추가했다. `serverPages`는 쪽 번호 → `[{id, hasBraille}]` 배열로, 서버가 그 쪽에 보유한 것으로 마지막으로 확인된 블록 id와 같은 id의 점자 항목 존재 여부다. 쪽을 서버에서 읽을 때와 명시적 저장이 서버에서 확인된 쪽에서만 갱신한다. 저장 요청은 이 기록으로 삭제된 블록·비어 버린 쪽·점자 패널 전송 여부를 정하며, 기록이 없는 쪽(v1·v2 파일, 읽지 않은 쪽)은 점자 패널을 건드리지 않고 `.smj`에만 보존한다고 알린다. `qualityReports`는 쪽 번호 → `[{severity, type, elementId, message}]`로 서버 `quality_report`의 `critical_errors`(`error`)와 `review_flags`(`review`)를 그대로 담는다. 쪽을 다시 읽으면 교체하며 누적하지 않는다. OCR 신뢰도 수치는 서버가 제공하지 않으므로 없다. v1·v2 파일은 두 필드를 빈 값으로 읽고 다음 명시적 저장에서 v3로 기록한다. v3 파일은 v2까지만 지원하는 앱에서 열리지 않는다(구버전 앱이 동기화 기록을 버린 채 저장하는 것을 막기 위한 이전 결정과 같은 이유).


2026-10-27 v4: 블록의 `clientId`, 문서의 `isTextJob`, 메모 작성자·답글·해결 시각을 보존한다. v1–v3는 누락 값을 안전하게 초기화한다. 서버 저장용 스냅샷은 첫 요청 전에 고정한다. 부분 실패 재시도는 그 스냅샷의 실패한 쪽만 보내며 `totalPages`를 반복하지 않는다. 전체 쪽 수는 텍스트 작업의 최초 저장에만 보낸다. 타 계정 작업 사본의 새 작업 ID는 현재 모델과 저장 파일 모두에 반영한다. 저장 중 새 편집은 완료 처리하지 않는다.
