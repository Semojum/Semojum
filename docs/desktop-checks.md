# Windows 데스크톱 검사

화면 작업 중에는 변경한 영역의 WPF 검사를 먼저 실행한다. 각 영역은 기존 검사 구현을 그대로 사용하며, 서로 독립된 출력 폴더에 결과를 기록한다.

```powershell
./scripts/check-desktop.ps1 -Area board
./scripts/check-desktop.ps1 -Area editor,appearance
```

| 영역 | 주요 검사 |
| --- | --- |
| `board` | 게시판의 목록·상세 표시와 목록 지연 |
| `institution` | 기관 계정·주문·요청 화면과 기관 데이터 처리 |
| `editor` | 원문·점자 표식, 셀 강조, 선택 연결과 원문 좌표 |
| `appearance` | 화면 설정 기본값, 공통 색상과 개별 컨트롤 상태 |

기본적으로 스크립트는 데스크톱 프로젝트를 한 번 빌드한 뒤 지정한 영역을 순서대로 검사한다. 이미 같은 소스를 빌드했다면 `-NoBuild`를 사용할 수 있다. 해당 옵션은 현재 소스와 실행 파일이 같은지 확인하지 않으므로, 소스를 수정한 뒤에는 다시 빌드해야 한다. 결과는 기본적으로 `artifacts/desktop-checks/<영역>/checks.txt`에 기록되며 실패한 경우 `failure.txt`에 이유가 남는다. `-OutputRoot`로 저장 위치를 바꿀 수 있다.

공통 표, 공통 버튼, 편집기와 설정처럼 여러 영역에서 쓰는 코드를 변경하면 영향을 받는 모든 영역을 지정한다. 영역별 검사는 전체 회귀 검사를 대체하지 않는다. 포함된 개별 검사 목록은 `WindowsFocusedChecks`에서 확인하고, 새 기능을 추가하면 해당 영역 목록과 전체 검사 양쪽에 등록한다. CI의 전체 Windows 스모크 및 실제 엔진 연동 검사는 최종 통합 확인을 위해 유지한다.

이 검사는 Windows에서 실제 WPF 화면을 사용한다. 전경 창이나 물리 입력을 사용할 수 없는 환경에서 일부 검사가 `SKIP`되면 별도로 확인해야 하며 통과로 계산하지 않는다.
