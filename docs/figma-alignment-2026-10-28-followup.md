## 캡처 방식 변경 — 96 DPI 레이아웃

이 PC의 주 모니터는 150% 배율(AppliedDPI 144)이다. 이전 캡처는 150%로 배치한 창을 96 DPI `RenderTargetBitmap`으로 그렸기 때문에 23 DIP 버튼이 22~23px로 흔들리고 테두리가 번지는 등 1px 단위 비교가 불가능했다. 이제 `--smoke-test`에서는 창을 만들기 전에 UI 스레드의 DPI 컨텍스트를 unaware로 바꿔 모든 창을 96 DPI로 배치한다(`App.xaml.cs`, 환경 변수 `SEMOJUM_SMOKE_DPI=native`로 끌 수 있다). `visual-geometry.json`에 실제 `Dpi: 96`을 기록한다. 일반 실행은 그대로 PerMonitorV2다.

## 남은 시각 차이 (FE)

- 메인 편집기(207:2631): Figma는 텍스트 2~3줄 선택과 4줄 캐럿, 점자 패널 동기 선택 상태다. 캡처 전 같은 캐럿·선택 상태를 만드는 스모크 단계가 필요하다. 글꼴 크기 선택기의 「30」은 Figma 예시값이다.
- 꼬리말 관리(207:4099): 마지막 범위가 「45 ~ 끝」, Figma는 「45 ~ 60」. 정렬 콤보의 화살표·행 높이 표현도 다르다.
- 알림(207:4537): Figma는 목록 전체를 테두리로 감싸고 구분선이 끝까지 닿는다.
- 도움말 트리 선택 띠가 세로선 1px 앞에서 끝난다. 메모·답글의 「」 글리프 폭, 분리 점자 창의 스크롤 위치(샘플 7줄)는 글꼴·데이터 제약이다.
- 100/125/150% 실제 배율 화면, 작은 창, 긴 한국어 문구 잘림은 96 DPI 캡처와 별개로 실제 배율에서 다시 봐야 한다. 150% 모니터에서 앱 자체는 PerMonitorV2로 동작한다.
