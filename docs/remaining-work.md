## 2. 서버 계약 또는 권한 결정과 함께 할 작업

UI 자체를 만드는 것은 FE에서 가능하다. 다음 항목은 화면을 만든 것만으로 실제 기능이 완료되지 않는다.

| 항목 | 현재 제약 | 다음 결정/연결 |
|---|---|---|
| 운영자 콘솔·답변 등록 2개 화면 | 앱 로그인은 WEB 운영자를 거절하고 서버 운영자 API는 APP 운영자를 거절한다. 레거시 null scope 가능성은 별도다. | 웹 전용으로 유지할지 앱 운영자 권한을 허용할지 정하고 역할 정책·로그인·목록/답변 API를 함께 검증한다. BE 권한 코드는 변경하지 않았다. |
| 암호 PDF 안내 | 업로드 요청에 비밀번호 필드가 없다. | 비밀번호 전달·실패 응답·재입력 정책을 정한 뒤 창을 업로드에 연결한다. |
| 스캔 PDF 확인 | 서버는 자동 OCR을 수행하고 현재 요청에 OCR 선택 필드가 없다. | 사전 판별/안내만 할지 OCR 선택을 제공할지 정하고 필요 시 계약을 추가한다. |
| 실패한 쪽 재변환·중단 작업 재개 | 해당 작업을 다시 시작/이어 처리하는 API가 없다. | 부분 재시도·재개·중복 차감 방지 계약을 제공한다. 현재 비활성 버튼은 성공 동작으로 가장하지 않는다. 변환 실패의 「다시 시도」는 같은 파일을 다시 업로드하는 흐름이다. |
| 크레딧 구매·결제 내역 | 일반 계정에 제공되는 구매/결제 흐름과 작업 재개 연결이 없다. | 권한별 조회·구매·처리 후 재개 흐름을 정한다. 현재 구매/문의는 문의 작성으로 연결한다. |
| 서버가 보존하지 않는 편집 옵션 | 일부 판면·꼬리말 범위는 SMJ에는 남지만 서버만 다시 열면 복원 범위가 제한된다. | 저장 계약 확장 또는 SMJ 우선 정책을 확정하고 회귀 검사한다. |
| 로그인 잠금 정책 문구 | 「5회 실패하면 10분 동안 잠깁니다」는 서버 코드 상수(`LoginAttemptService`)에서 가져온 고정 문구다. | 정책이 바뀌거나 응답에 한도 값이 실리면 문구를 응답 기준으로 바꾼다. |

Figma 59개 중 대응 화면이 없는 4개는 운영자 콘솔, 운영자 답변 등록, 암호 PDF, 스캔 PDF 확인이다. 인식 불가 자동 안내는 FE에서 구현했다. 나머지도 모두 ‘현재 FE로 불가능’한 것은 아니다. 앞의 두 표처럼 정책·계약 의존 여부를 구분한다.

## 3. 실제 환경에서 남은 검증

- 외부 앱으로 전환하거나 창을 비활성화하는 순간의 마지막 한글 조합 글자 보존. 같은 창 안의 포커스 이동은 이미 실키보드로 확인했다.
- 점자 프린터의 실제 출력·면 범위·꼬리말·용지, 스크린리더의 이름·순서·상태 읽기. 현재 추가 장비가 없어 실기기 통과로 기록하지 않는다.
- 여러 모니터·작업 영역·배율 조합, 키보드만으로 모든 팝업과 도움말 접근.
- 수정본의 실제 로그인부터 저장·재열기까지 최종 UI 시나리오. 이전 실서버 API 66개 통과와 이번 로컬 WPF 검증을 구분한다. 새 게시글·답변·구매를 전송하는 검증은 별도 허용 범위 안에서만 실행한다.
- GitHub Actions는 계정 결제/지출 한도 문제로 작업이 시작되지 않는다. 원격 검증은 미완료다.

## 승인된 예외와 이미 완료된 사항

- 범위 지정 저장 520×240, 페이지 설정 480×280: Figma의 입력칸/버튼 겹침을 없애기 위해 사용자가 창 높이 증가를 선택했다. 행 간격은 설계를 따른다.
- 메뉴 6종의 항목·순서·팝업 크기, 보기 토글·패널 복원, 동봉 글꼴의 실제 렌더링 경로, 현재 줄 왼쪽 여백, 게시글 메타데이터 간격은 1차 수정에 포함됐다.
- WPF 159개(96 DPI와 150% 네이티브 각각)와 코어/동봉 엔진 78개가 통과했다. 기존 실서버 검증용 비밀글은 삭제 확인까지 완료했다.
