## 변경

- 엔진을 v3.4.35, 커밋 `74f76d15f3ac6f87c52d75a25882cc580508e51f`에 고정했다. 실행 중 엔진의 ping 결과를 정보 창에 표시한다.
- 최초 점자와 신규 블록을 안정적인 공통 ID로 저장한다. 저장 요청은 고정된 스냅샷을 사용하고 부분 실패는 실패한 쪽만 명시적으로 재시도한다. 타 계정 작업 사본의 새 ID를 로컬 파일에도 기록한다. 전체 쪽 수 갱신은 텍스트 작업에만 적용한다.
- `.smj` v4에 클라이언트 ID, 작업 유형, 메모 작성자·답글·해결 시각을 보존한다. v1–v3를 읽는다. 저장 중 추가 편집은 미저장 상태로 남긴다.
- 기본 텍스트 화면을 같은 원본 쪽의 연속 편집으로 바꿨다. 검색과 메모는 원래 블록·줄 좌표로 연결한다. 들여쓰기 태그는 원문 바이트를 바꾸지 않고 화면에 공간을 그린다.
- 열기 설정을 한 창으로 통합했다. 서버 설정 조회가 실패해도 기존 `.smj`는 연다. 저장 형식, 범위 지정 저장, 점자 대상 찾기, 결과 순번, 닫기 버튼을 반영했다.
- 메모 입력/말풍선, 수식 23기호·편집 가능한 점자 결과, 적용 규정 표·전문, 양식 저장/사본/삭제, 꼬리말 입력/이어가기, 기본 옵션·설명 유형, 계층 도움말을 반영했다.
- 메뉴의 제외 항목을 숨기고 삽입을 다섯 묶음으로 나눴다. 설정 메뉴와 도구막대의 기본 점역 옵션 진입점을 통일했다. 상태줄에 옵션과 계정 ID를 표시하고 세 패널의 현재 위치 강조를 노랑으로 맞췄다.
- 상태줄을 옵션 전용으로 바꾸면서 가려질 수 있는 비동기 수신·원본 다운로드 오류는 닫을 수 있는 안내 띠에 표시한다.
- 기존 네이티브 한글 입력 방식을 유지하며, 포커스 이동·편집기 안 클릭·명령·닫기 전에 미확정 조합을 확정하도록 보완했다. WPF 입력 경로로 전환하는 방식은 사용자 의견에 따라 채택하지 않았다.
- 사용량은 서버 계약의 쪽 단위로 표시한다. 유형별 쪽수/비율, 진행 막대, 다섯 세로 항목, 한국어 작업 상태를 제공한다. 일반 계정에 없는 결제 조회는 ‘내역 없음’으로 가장하지 않고 제한을 표시한다.

## 사용자가 확정한 시각 자료 정책

모든 초안을 보존하고 기본 선택만 바꾼다. 새 업로드 결과를 처음 받을 때 계정 설정을 적용한다. 기존 서버 작업·저장 파일을 다시 열 때는 마지막 선택을 유지한다. 체크하지 않은 초안도 목록과 작업 파일에 남긴다.

현재 초안 이름과 정확히 일치하는 항목을 우선한다. QA에서 통합되었다고 명시한 짧은 제목·개조식·상세·줄글은 현행 ‘설명’ 또는 ‘기본’에 대응한다. 생략/별책 참조는 각각 해당 생략/참조 초안을 선택한다. 대응 항목이 없으면 기존 선택을 유지한다. 표는 실제 엔진의 `table_grid`, `linear`, `transposed`, `unfold`를 사용한다. 실제 AI의 `chart_graph` 유형도 그래프 설정으로 연결한다. 이는 받은 결과의 선택 정책이며 AI가 생성하는 초안 수를 바꾸지 않는다.

## 남은 확인

실서버 저장/재열기, 1쪽 AI 변환, 대기 작업 중단, 사용자 양식 CRUD, 비밀글 등록·수정·첨부·삭제 검증은 완료했다. 운영자 답변, 물리 동시 입력·보조기기·다중 모니터/DPI·인쇄·운영 업데이트는 검증하지 않았다. 한국어 IME 수정본에서 직접 입력한 문장과 공백은 보존되었으며, 미확정 마지막 글자의 포커스 이동 검증이 남았다. 6점키 1/3단 배열은 기존 합의대로 추가 근거가 있을 때 반영하며 현재 지원 키를 임의로 바꾸지 않는다. BE 변경·관리자 웹, 서버 폴더·휴지통, 엔진의 영어 문서·혼용·연속 공백 확장은 합의된 후속 범위다. 서버 미지원 설정은 .smj에 보존하고 서버 저장 결과에 안내한다.

커밋·푸시·PR·배포 업로드는 하지 않았다. 검증용 빌드와 소스는 로컬 산출물이다.

### 실사용 환경 후속 확인

사용자는 추가 점자 프린터·스크린리더 장비가 현재 없다고 확인했다. 등록된 일반/가상 프린터에 점자 출력 데이터를 보내지 않았다. 자동 입력 도구가 영문 키를 그대로 전달해 실제 한글 조합은 사용자 직접 입력으로 확인했다. 첫 검증 창에는 `검증: 한글입력테스`가 남아 실패로 기록했다. 그 창은 진단 목적으로 PreferredImeState=On을 설정했으므로 공백 누락을 제품 기본 설정의 확정 원인으로 일반화하지 않는다.

비교 진단에서는 기본 AvalonEdit에서 `글` 조합 중 포커스를 잃자 해당 음절이 문서에 들어오지 않는 것을 기록했다. Tab 등으로 조합을 먼저 확정하면 전체 문구를 유지했다. [AvalonEdit의 포커스 이탈 처리](https://github.com/icsharpcode/AvalonEdit/blob/master/ICSharpCode.AvalonEdit/Editing/ImeSupport.cs)는 미확정 조합을 [CPS_CANCEL로 취소](https://github.com/icsharpcode/AvalonEdit/blob/master/ICSharpCode.AvalonEdit/Editing/ImeNativeWrapper.cs)한다. 이를 앞서 CPS_COMPLETE로 확정하는 처리를 추가했다. 입력 방식은 기존 네이티브 경로를 유지한다.

수정본 검증 창은 제품 기본 IME 설정을 그대로 사용하며, 사용자 입력 `검증: 한글 입력 텍스트`를 원문·화면·점역에 보존했다. Space로 마지막 음절을 확정한 기록이 있어, 이것만으로 미확정 상태에서의 포커스 이동까지 통과로 보지 않는다. Space·Enter·Tab 없이 `가`를 입력하고 검색 칸을 클릭하는 최종 확인을 요청한 상태다. 검증 창과 배포 폴더의 앱/코어 DLL 해시는 일치한다.

게시판은 검증용 비밀글의 제목·본문·TXT 첨부와 등록→수정→삭제 순서를 제시하고 사용자 승인을 받은 뒤 실행했다. 2026-10-27 11:45 KST에 12개 검사를 통과하고 게시물 ID 2를 삭제했다. 다른 사용자의 글이나 운영자 권한은 검사하지 않았다.
