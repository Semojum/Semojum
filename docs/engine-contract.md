# 로컬 점역 엔진 계약과 설계 차이

확인일: 2026-10-20. 서비스 기획이 요구사항의 기준이며, 사용자 결정에 따라 어댑터는 **실제 엔진 코드**를 사용한다. 지원되지 않는 요구를 자체 점역 규칙으로 추측하지 않는다.

2026-10-22 Windows 인수 수정: [Semojum/braille v3.4.31, 9b64349](https://github.com/Semojum/braille/tree/9b6434996bdeffa2536551d20cf2bdbcb82ecab5)로 고정 버전을 갱신했다. 기존 v3.4.24 어댑터의 급수·표·기호·역점역과 앱 `compose_editor` 경로를 실제 Python/패키징 엔진으로 재검사했다. Python 조판 5개(160개 난수 parity/좌표 사례 포함), 실제 엔진 포함 핵심 66개가 통과했다. upstream `footer_mode`·`footers_by_orig_page`를 앱 필드로 임의 변환하지 않고, 기존 인쇄 면 기준 범위·정렬을 앱 조판 브리지에서 유지한다.

v3.4.31의 실제 `sidecar.translate`도 영어 문서 규정·혼용 규정·연속 공백 정책 필드를 제공하지 않는다. 이 옵션의 엔진 후속 범위는 그대로이며, 새 버전으로 올렸다는 이유만으로 지원 완료로 표시하지 않는다.

| 항목 | 실제 계약과 앱 처리 |
|---|---|
| 급수 | `korean_grade`, `english_grade` 정수 1/2. 한글·영문 급수 옵션 전달 |
| 선택지 | `split_choices` 지원. 한 줄 하나/짧으면 합치기 전달 |
| 표 | `translate`가 `<!표>` 구조를 받으며 초안·render_mode를 반환. 예전 `table_source`는 별도 table 명령 경로 유지. 앱의 표 편집 창은 셀→태그 구조로 저장 |
| 수식 | `<!수식>`을 감싸서 전달. 엔진이 BAD_LATEX·TOO_LONG을 반환할 수 있음 |
| 원문 길이 | 태그를 뺀 묵자 1,000자 제한. 평문 TXT는 유니코드 경계를 보존해 나눔. 태그 문서는 중첩 구조를 임의로 분리하지 않으며 엔진 길이 오류를 표시 |
| 태그 | `unknown_tags`와 dropped/blocked를 실제 응답대로 보존 |
| 기호 | `symbols` 명령으로 엔진 제공 기호 표 사용 |
| 조판 | upstream `build_brf`는 유지. 앱은 `scripts/engine-entry.py`의 `compose_editor` 명령으로 `editor_composition.py`를 호출. `assist`의 wrap·정렬·숫자·괘선 및 BRF 직렬화/복원 함수를 재사용하고 조판 정책과 셀 좌표를 추가 |
| 머리말 | 원문 삽입 위치까지 실제 점역·조판해 현재 면부터 적용. 앞선 면은 유지하고 빈 값은 해제. 수동 점자와 원문 위치가 맞지 않으면 재점역 또는 블록 시작 삽입 안내 |
| 페이지행 | upstream JSON은 odd/every만 노출. 앱 브리지는 내부 함수가 지원하는 even/none, 변경선 표시, 인쇄 면 번호 범위를 연결. none이고 꼬리말도 없는 면은 페이지행 공간을 본문에 반환 |
| 꼬리말 | 기본 값, 시작·끝/끝까지/빈 내용으로 숨김, 범위별 left/center/right. 페이지 번호 출력 정책과 독립적으로 필요한 면에 꼬리말 행 생성. 서버 save는 기본 텍스트만 받으므로 범위·정렬은 .smj 보존 |
| 쪽·장바꿈 | translate가 버리는 조판 표식을 앱에서 분리·보존하여 조판에 전달. 본문 가운데의 표식과 반복 쪽바꿈도 지원. 두 번 쪽바꿈의 빈 면은 Service 요구에 따라 보존하며 upstream의 연속 break 생략과 다름 |
| 판면 적용 범위 | Service 조판 HTML §5-6에 따라 작업 전체 한 세트. `editScope`는 이전 파일/API 호환 필드이며 면별 판면 설정으로 해석하지 않음 |
| 언어·공백 | 영어 문서 규정·한영 혼용·연속 공백 정책은 translate 대응 필드가 없음. 설정 화면에 한계를 표시하고 값을 보존. 사용자는 엔진 확장을 후속 범위로 확정. `force_roman`을 일반 영어 문서 옵션으로 오용하지 않음 |
| 검수 등급 | grade는 확인 우선순위이며 정확도 또는 검수 완료 판정이 아님 |

## 실행과 오류 처리

UTF-8 JSONL 요청/응답의 id, 시작 ping의 protocol=1을 검사한다. stderr는 별도로 비우고 내용을 저장하지 않는다. 취소·시간 초과·응답 오류 후 프로세스를 정리한다. 실패 때 샘플 점자를 대신 반환하지 않는다.

0.4초 내 응답이 없으면 점자 입력을 잠그고 지연 상태를 알린다. 원문 편집과 명시적 저장은 유지한다. 엔진의 최초 시작을 허용하기 위해 요청은 제한 시간 내에서 계속 기다리며, 현재 요청의 응답이 오면 점자 잠금을 해제한다. 원문·메타데이터·수동 점자·요청 세대가 바뀐 응답은 적용하지 않는다.

## 조판 좌표와 직접 편집

`compose_editor`는 `brf`, `pages`, `maps`, `ends`, `kinds`, `numbers`를 함께 반환한다. `pages`는 반환 BRF를 디코딩한 값이며 내보내기·미리보기·편집 모눈이 공유한다. 각 본문 칸의 좌표는 블록 ID와 저장 문자열 오프셋이다. 같은 문장이 반복되어도 전체 문자열 검색으로 위치를 추측하지 않는다. 각 논리 줄의 실제 wrap 결과를 원문에 연결하고, 생략된 부분이 공백인지 확인한다. CRLF/CR/LF와 탭을 처리하면서 저장 문자열 오프셋을 보존한다.

생성 머리말·페이지행·변경선·괘선에는 편집 좌표를 주지 않는다. 연속 쪽바꿈으로 만든 빈 면에도 원문 삽입 위치를 제공한다. 본문 뒤 빈칸 입력은 명시적 입력 시에만 공백/개행을 삽입한다. 그리드 선택 복사는 조판 표식을 제외하고 본문 교체는 기존 표식을 보존한다. 화면 폭 변화나 soft wrap은 저장 내용을 바꾸지 않는다. 갱신 중인 조판의 마우스 좌표는 사용하지 않으며 현재 원문 caret에 대한 연속 키 입력은 보존한다.

앱은 외부 엔진 저장소의 번역 규칙을 수정하지 않았다. 앱 조판 브리지는 고정된 내부 API에 의존하므로 엔진 버전 변경 시 parity/좌표 검사를 먼저 통과해야 한다.

## 검증과 미검증 범위

실제 Python v3.4.31로 급수, 표 초안, 알 수 없는 태그, 기호, 검수 순서, BRF 생성·복원을 검사한다. Windows 패키징 엔진도 별도 CI로 검사한다. 전체 점역 정확도·모든 수식과 표·실제 점자 프린터의 물리 출력은 이 검사로 보증되지 않는다. 라이선스·NOTICE·third_party 고지는 배포물에 포함하고 kiwi는 번들하지 않는다.

`tests/engine/test_editor_composition.py`는 160개 난수 조합에서 기존 지원 범위의 BRF가 upstream과 같은지, 모든 본문 셀이 올바른 원문 위치인지 확인한다. 변경선 끄기·번호 없음의 공간 회수·독립 꼬리말·번호 범위·반복 쪽바꿈·개행 정규화는 별도 기대 결과로 검사한다. 이는 해당 사례의 조판 정합성 근거이며 한국 점자 규정 전체의 정확도 인증은 아니다.
