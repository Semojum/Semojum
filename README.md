# 세모점 · Windows 데스크톱 목업

Figma **세모점 에디터 V2 · UI 화면 2026-10-10**을 바탕으로 만든 WPF 시안입니다. 원본·텍스트·점자 3패널을 중심으로 실제 편집 동작을 확인할 수 있습니다.

**점역 결과는 고정 샘플입니다. 실제 한글·수식 점역 정확도를 검증하거나 제작용 점자 문서로 사용할 수 없습니다.**

## 실행

### Windows 실행 파일

`Semojum-win-x64.zip`을 풀고 **Semojum.Mockup.exe**를 실행합니다. 폴더 전체가 필요하며 .NET 설치는 필요하지 않습니다. GitHub Actions의 **Windows mockup → Artifacts → Semojum-win-x64**에서도 받을 수 있습니다.

### 소스에서 실행

Windows와 [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0)가 필요합니다. `Run-Mockup.cmd`를 실행하거나:

```powershell
dotnet run --project src/Semojum.Desktop -c Release
```

현재 시안의 최소 창 크기는 1280×800 DIP입니다. macOS/Linux에서는 핵심 로직 테스트와 Windows 교차 빌드만 가능하며 WPF 앱 실행은 지원하지 않습니다.

## 체험 순서

1. 원본·텍스트·점자 3패널에서 샘플 문서와 블록 선택을 확인합니다. 구분선을 끌어 패널 너비를 조절할 수 있습니다.
2. 원문 일부를 선택하고 **강조 / 점역자 주 / 수식**을 삽입합니다. 태그는 파란색으로 표시됩니다. Ctrl+Z로 되돌립니다.
3. **6점 입력**을 켜고 점자 편집기에서 `F D S J K L`을 함께 눌렀다 놓습니다. 점 1–6에 대응하며 여섯 키를 모두 누르면 `⠿`가 들어갑니다.
4. 점자 패널의 **↗**를 눌러 창을 분리하고 편집한 뒤, 창을 닫아 합칩니다. 두 화면은 같은 편집 버퍼를 공유합니다.
5. 점자를 직접 수정한 후 원문을 변경하고 다음 블록으로 이동합니다. **유지 / 덮어쓰기 / 취소**를 선택할 수 있습니다. 덮어쓰기는 고정 샘플 점자로 되돌립니다.
6. **정보 → 점역 응답 지연 체험**을 켜고 **점역 미리보기**를 누릅니다. 0.4초 후 해당 점자 패널만 잠기고, 원문 편집과 저장은 계속 가능합니다. 재시도하면 지연 체험을 끄고 잠금을 해제합니다.
7. **판면 설정**, **6점키 설정**, **메모**, **수식 입력창**을 확인합니다. 수식은 LaTeX 미리보기 후 원문 태그로 삽입됩니다.
8. Ctrl+S로 `.mock.smi`에 저장하고 다시 엽니다. 원문·점자·메모·직접 수정 여부·판면 설정이 보존됩니다.

## 구현 범위

| 기능 | 상태 |
| --- | --- |
| 3패널, 크기 조절, 원본 숨기기, 글자 크기 | 동작 |
| 원문 편집, 블록별 실행 취소, 찾아 바꾸기, 태그, 메모 | 동작 |
| 점자 직접 수정, Unicode 점자 붙여넣기, 6점 동시 입력 | 동작 · 키보드 동시 입력 한계는 하드웨어에 따름 |
| 점자 창 분리/합치기, 블록 동기화 | 동일 문서 버퍼 공유 |
| 수식 | WpfMath LaTeX 미리보기 · 점역 미연동 |
| 판면 | 설정 저장 및 줄당 칸 수 초과 표시 · 자동 페이지 배치 미구현 |
| 저장/열기 | 목업 전용 JSON `.mock.smi`, 최대 20 MB |
| 텍스트 가져오기/내보내기 | UTF-8 `.txt`, 가져오기는 한 블록, 내보내기는 현재 블록 |
| 원본 미리보기 | XAML로 그린 샘플 자료 · 실제 PDF 렌더링 아님 |
| 점역 엔진 | 고정 샘플 반환, 0.4초 지연/재시도 시뮬레이션 |
| PDF/HWP/HWPX·이미지 변환, 인쇄, 계정, 서버, 자동 저장 | 미구현 |

`.mock.smi`는 제품의 최종 SMI 규격과 별개입니다. 일반 `.smi`/문서 파일을 목업 작업 파일로 해석하지 않습니다. 열린 작업 파일의 원본 미리보기는 제공하지 않습니다. 6점키 및 자동 점역 옵션은 실행 중에만 유지됩니다.

## 구성과 선택 이유

- **C# / WPF / .NET 10**: Windows 전용 창·입력·메뉴 구현. 브라우저 런타임을 포함하지 않습니다.
- **AvalonEdit**: 원문/점자 텍스트 편집, 태그 색상, 실행 취소. 블록별 `TextDocument`를 재사용하며 분리 창에서도 버퍼를 공유합니다.
- **CommunityToolkit.Mvvm**: 관찰 가능한 문서 상태와 명령. 파일·점역·입력 로직은 UI와 분리했습니다.
- **WpfMath**: LaTeX 미리보기. 최종 수식 점역 엔진과는 독립적입니다.

```text
src/Semojum.Core/          문서 상태, 저장, 6점 입력, 비동기 점역 조정
src/Semojum.Desktop/       WPF 화면, 편집 버퍼, 설정 창, Windows UI 검사
tests/Semojum.Core.Tests/  외부 테스트 프레임워크 없이 실행하는 핵심 동작 검사
scripts/publish.ps1        자체 런타임 포함 Windows ZIP 생성
```

샘플은 세 블록으로 구성했습니다. 활성 블록의 편집기만 표시하고, 늦게 도착한 점역 결과가 새 원문이나 직접 수정한 점자를 덮어쓰지 않게 버전과 요청 순서를 확인합니다. **대용량 문서의 성능 수치를 측정한 상태는 아닙니다.** 실제 엔진·문서 변환기 연결 후 입력 지연, 메모리, 시작 시간, 여러 창에서의 동작을 Windows 장비로 측정해야 합니다.

## 검증 및 배포

```powershell
dotnet build Semojum.sln -c Release
dotnet run --project tests/Semojum.Core.Tests -c Release
./scripts/publish.ps1
# Windows ARM64 패키지
./scripts/publish.ps1 -Runtime win-arm64
```

핵심 검사는 6점키 조합/초기화, 직접 수정 보호, 응답 역전, 지연·실패·재시도, 저장 중 변경 감지, Unicode 저장/복원, 잘못된 작업 파일 거부를 다룹니다.

Windows UI 검사:

```powershell
./artifacts/Semojum-win-x64/Semojum.Mockup.exe --smoke-test ./artifacts/smoke
```

실제 WPF 화면을 PNG로 기록하고 창 분리의 버퍼 공유, 태그 실행 취소, 블록 이동, 점자 잠금, 저장을 확인합니다. GitHub Actions에서 동일 절차를 실행하고 **wpf-smoke** 아티팩트에 결과를 보관합니다. 물리 키보드 동시 입력, 한국어 IME, 보조기기 및 여러 DPI의 화면은 수동 확인이 필요합니다.
